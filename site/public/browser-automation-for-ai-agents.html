Tabrelay / Browser automation for AI agents

Browser automation for AI agents that use your existing session

An AI coding agent that can run shell commands can use a browser too, if the browser has a command-line door. Tabrelay is that door for the Chrome you are already logged in to, with limits you set.

What agents need from a browser

Agents that run on your computer usually need three things from a browser: a way to act (open, click, type, run JavaScript, upload), a way to see (evaluate the page, take a screenshot), and access to the accounts you use. Starting a fresh automation browser gives the first two but not the third; you would have to log the agent in, which means giving it credentials or a second set of sessions to maintain.

A CLI is the simplest agent interface

Tabrelay's actions are plain shell commands that print text or JSON and exit non-zero on failure. Any agent that can run a command, such as Claude Code with its shell tool, can use it with no extra protocol:

TAB=$(tabrelay open https://example.com/)
tabrelay eval "$TAB" 'document.title'
tabrelay shot "$TAB" /tmp/page.png      # the agent can read the image
tabrelay close "$TAB"

What about MCP?

Tabrelay does not ship an MCP server, and it contains no AI model of its own. It is a primitive: the agent decides what to do and Tabrelay carries it out in your browser. With an agent that has a shell tool, you do not need MCP at all. If your agent can only use MCP tools, you would have to wrap the CLI in an MCP server yourself; the commands are simple enough to make that straightforward, but that wrapper is not part of Tabrelay. For MCP servers that do exist for browsers, see the comparison with Playwright MCP, browser-use and Claude in Chrome.

Give the agent your session, but fence it in

Your logged-in browser is powerful, so the limits matter more than the features. Tabrelay has these:

  • Allow-list. The extension acts only on https pages whose host is on a list you edit in the extension's options page. Nothing the command line sends can widen it, so an agent cannot add sites.
  • Local token. The server only accepts jobs that carry a random secret, and the extension only runs jobs that carry it.
  • Localhost only. The server binds to 127.0.0.1 and refuses foreign Host headers and web page origins, so websites you visit cannot drive it.
  • Visible. Chrome shows its "started debugging this browser" bar while Tabrelay works on a tab.

These are guard rails, not a sandbox: any program running as you can read the token file, and JavaScript in an allowed page can do whatever that page can do. More in letting an AI agent use your logged-in browser safely.

Several profiles, one agent

If you use different Chrome profiles for different accounts, load the extension in each. Each copy reports the Google account its profile is signed in to, and you choose one with the profile setting or the TABRELAY_PROFILE variable. Every job goes to exactly one profile.

Tell the agent how to use it

Add a few lines to your agent's instruction file (such as CLAUDE.md or AGENTS.md): the commands above, the rule that it may only touch the sites on the allow-list, a request to use --draft on posting scripts and to close or detach tabs when done. See the command reference.

Frequently asked questions

Is Tabrelay an MCP server?

No. It is a command-line tool and a Chrome extension. Agents with a shell tool can run it directly. If you need an MCP interface you would wrap the CLI yourself.

Which AI agents can use it?

Any agent or script that can run a shell command. Tabrelay does not depend on a particular model or agent.

Can the agent visit any site in my browser?

No. The extension acts only on sites on the allow-list you edit in its options page, and the command line cannot change that list.

Does Tabrelay send my browsing data anywhere?

No. The extension talks to 127.0.0.1:47833 and to the pages it drives, nothing else. There is no telemetry.
